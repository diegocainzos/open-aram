## Findings
- [ ] **[high]** `client/game.ts:41-45` + `client/game.ts:178` / `client/game.ts:58` - Module state `views`, `projViews`, `tweens`, `relicObjs`, `bushObjs`, `pingMarks` is never reset and the old scene never disposed between matches. `stop()` only kills rAF/music/key listeners; `prepare()` builds a fresh `scene` and pushes 4 more `relicObjs`/`bushObjs`. Structure ids `st{team}{0..3}`, minion ids `m{n}`, projectile ids and `"mercadona"` repeat every match, so in match #2 `syncUnits`/`syncProjectiles` (`game.ts:286`, `game.ts:459`) find stale Views whose `obj` lives in the discarded scene and never `scene.add` them → towers/Urna/Congreso/pigeons/projectiles invisible, their health bars are detached DOM (wiped by `bars.innerHTML=""` at `game.ts:182`), `loop()`'s `relicObjs[i]` (`game.ts:211`) updates game-1 objects so relic visibility is frozen, bush fade affects dead tarps, and the 70 `dur: Infinity` rock tweens from each `prepare()` (`game.ts:126`) accumulate forever. Fix: at the top of `prepare()` do `views.clear(); projViews.clear(); tweens.length = 0; relicObjs.length = 0; bushObjs.length = 0; pingMarks = []; hud` reset (and dispose the previous scene).
- [ ] **[med]** `client/main.ts:123` / `client/main.ts:261-265` - Loading→game race: server starts the match on its 20 s timeout regardless of the client's `await import("./game")` (`main.ts:245`) or `await gameMod.prepare(...)` (`main.ts:247`). If either is still pending, `gameMod!.start(...)` throws a TypeError inside the `onStateChange` callback (game never renders, listener chain breaks), or `start()` runs against a half-built scene. Fix: store the `loading()` promise and gate the `game` branch on it (`loadingP.then(() => { if (gameMod && !gameMod.running()) startGame(); })`), plus `if (!gameMod) return;` in `startGame()`.
- [ ] **[med]** `client/game.ts:850-855` - `cv.addEventListener("mousedown"…)`, `cv.addEventListener("mousemove"…)` and `window.addEventListener("mouseup"…)` are added every `bindInput()` and never removed (`stop()` at `game.ts:178` only removes keydown/keyup), while `#gl` persists across matches → after N matches a held right-click drag sends N `move` messages per 120 ms. Fix: assign `cv.onmousedown = …` (property, auto-replaced) or `removeEventListener` in `stop()`.
- [ ] **[med]** `client/style.css:150` (with `client/style.css:97` `.hud * { pointer-events: auto }`) - `.hudchat`'s own 360px-wide box is a hit target (only `.log` is `.nopoint` and the input is `display:none` when closed), so once chat lines exist (up to 12, ~200px tall) that strip above the left HUD swallows right-click move/attack orders. Fix: `.hudchat { pointer-events: none } .hudchat input { pointer-events: auto }`.
- [ ] **[med]** `client/models.ts:45` (`textSprite`), `client/game.ts:439` (`projMesh`), `client/game.ts:471` (`burst`), `client/game.ts:474` (`ring`), `client/game.ts:493` (`sprite3d`) - Per-call geometry + material (and a 512×128 `CanvasTexture` per text sprite) are only `scene.remove`d; nothing calls `dispose()` anywhere in the client, so GPU buffers/textures leak monotonically within a match (bursts per kill, 80 paper planes per nexus, one texture per stun stars/zzz/ping) and across matches via the dropped scenes. Fix: `o.geometry.dispose(); (o.material as THREE.Material).dispose()` in each tween's `end` and in the `setTimeout` removal paths (incl. `textSprite`'s `map.dispose()`).
- [ ] **[low]** `client/audio.ts:77-85` - `speak()` never cancels or limits the queue (only the Torrente-penta path in `onKill` calls `speechSynthesis.cancel()`), so kill lines + banter + fx lines ("¡Tibbers!", "¡Mortadelooo!") stack and play seconds late/overlapping. Fix: `speechSynthesis.cancel()` before announcer/`voice` lines.
- [ ] **[low]** `client/main.ts:39-53` - An in-flight `/rooms` fetch resolving after `enter()`/screen swap dereferences `$("q")`/`$("list")` which are now null → TypeError in the async task on every join-mid-poll. Fix: `if (!document.getElementById("list")) return;` first in `render()`.
- [ ] **[low]** `client/game.ts:873` (`keysDown`) - Never cleared on window blur; a `keyup` lost to a focus switch swallows the next press of that key (Q/W/E/R silently dead once). Fix: `window.addEventListener("blur", () => keysDown.clear())` in `bindInput()`.
- [ ] **[low]** `client/main.ts:115` - `chatLog` grows unbounded (rendered slice `-60`, 6 seeded into the game HUD). Fix: trim on push (`if (chatLog.length > 200) chatLog.shift()`).
